# Marine Debris Detection 项目阶段性快照总结（2025-12）

本文件为阶段性项目快照，主要覆盖 2025-12-23 至 2025-12-27 的实验结论与管理判断。

用途：帮助在一段时间未接触项目后，快速恢复当时的技术主线、实验结论和后续阅读路径。

## 1. 项目目标与阶段状态

### 1.1 阶段目标

本项目聚焦海洋垃圾检测，使用 MARIDA 多光谱遥感数据与 YOLO 系列检测框架，目标是在工程上形成一条可复现、可分析、可写论文的检测路线。

### 1.2 2025-12 下旬阶段状态

截至本快照阶段，项目已经形成以下判断：

- 已建立基本可复现实验链路：数据处理 -> 训练 -> 对比/消融 -> 结果总结。
- 已获得当时阶段性主线方案：`7ch + Knowledge Heatmap + CIoU`。
- 已完成 10ch 的 IoU Loss 消融实验：`CIoU / EIoU / SIoU / SIoU + Heatmap`。
- 已积累论文写作所需的主要素材：主结果、对照实验、失败案例与工程经验。

### 1.3 时间锚点

- 7ch 主线结论主要对应 `2025-12-23` 至 `2025-12-25`。
- 10ch 消融结论补充到 `2025-12-27`。
- 因此本文件应被理解为“阶段性收敛总结”，不是全项目最终归档。

## 2. 当时的主线方案为何是 7ch

### 2.1 阶段性最优主线

在本快照时间点，阶段性最优主线为：

- 模型：`YOLOv11n`
- 输入：`7ch` 多通道 `.npy`
- 结构：Ultralytics + 自定义 dataset/trainer
- 关键设计：第 7 通道为基于 GT mask 距离变换生成的 `knowledge heatmap`
- 损失：`CIoU`

对应的阶段性主结果为：

- Precision: `0.6281`
- Recall: `0.7351`
- F1: `0.6774`
- mAP50: `0.6673`
- Best Epoch: `38`

这组结果对应当时用于对齐 SOTA 的 7ch baseline 训练，是本阶段做路线选择时最重要的依据。

### 2.2 7ch 输入结构

当时主线 7ch 输入可以概括为：

- RGB 可见光信息
- NIR 近红外信息
- 关键谱段信息
- 由 GT mask 生成的 knowledge heatmap

项目中的 knowledge channel 不是在线蒸馏，而是离线预处理生成的输入级先验信息。其核心作用是把目标区域的空间先验直接编码进输入张量，帮助模型更稳定地感知目标中心区域。

### 2.3 当时认为 7ch 更优的原因

在 2025-12 下旬，团队对 7ch 主线的判断主要来自以下几点：

- 它在综合指标上优于当时 10ch 的最优组合。
- 它在 Recall 上优势明显，更贴合海洋垃圾检测“宁可多报、不能漏报太多”的任务倾向。
- 它在工程复杂度与收益之间更平衡，便于写成清晰的方法主线。

## 3. 项目技术骨架

### 3.1 数据与配置

本阶段使用的数据集事实如下：

- 7ch 数据规模：`train=347 / val=114 / test=53`
- 10ch 数据规模：`train=347 / val=114 / test=53`
- 7ch 配置文件：`configs/datasets/marida_mask_rescue_7ch.yaml`
- 10ch 配置文件：`configs/datasets/marida_mask_rescue_10ch.yaml`

### 3.2 数据形态

- 输入以多通道 `.npy` 张量为主。
- 训练配置通过 YAML 指定通道数与数据路径。
- 7ch 与 10ch 使用相同样本划分，便于阶段内横向比较。

### 3.3 训练框架

本项目在当时已经不是纯原生 Ultralytics 用法，而是带有明显定制化：

- 自定义 Dataset：用于多通道 `.npy` 输入加载
- 自定义 Trainer：用于适配训练流程与采样策略
- 自定义知识通道生成脚本：用于生成第 7 通道 heatmap

这意味着项目的核心不只是“换几个通道训练”，而是已经形成了一套面向多光谱海洋垃圾检测的专用工程路径。

## 4. 10ch 消融结论与失败原因

### 4.1 10ch 消融结果

在本快照阶段，10ch 体系已经完成以下对比：

- Exp-A：`10ch + CIoU`
  - F1 = `0.462`
  - Recall = `0.314`
- Exp-B：`10ch + EIoU`
  - 与 Exp-A 基本一致
  - 无明显提升
- Exp-C：`10ch + SIoU`
  - F1 = `0.628`
  - Recall = `0.620`
  - 为 10ch 体系内最优
- Exp-D：`10ch + SIoU + Heatmap`
  - F1 = `0.526`
  - 出现回退

### 4.2 阶段性判断

在该阶段，团队对 10ch 的结论是：

- `SIoU` 对 10ch 确实有效，能够明显修复早期 Recall 偏低的问题。
- 但 10ch 的最好结果仍未超过 7ch 主线。
- 因此从论文主线和工程主线的角度，当时没有切换到 10ch。

### 4.3 失败原因与经验

当时沉淀下来的关键经验包括：

- `auto_augment=randaugment` 会破坏 knowledge channel 的空间先验。
- 过强增强会伤害小目标和精细空间结构。
- 过快学习率衰减会限制中后期优化。
- 过早 early stopping 会错过真正的最佳 epoch。
- `SIoU` 在 10ch 上有效，但与额外 heatmap 叠加后可能产生冲突。

换句话说，当时项目已经不再是“多加通道就一定更好”，而是进入了“通道设计、损失函数、增强策略三者耦合”的阶段。
