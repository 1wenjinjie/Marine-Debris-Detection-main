# 场景交叉验证下的 2×2 审计：预注册分析计划（v1）

状态：在任何一次 2×2 交叉验证训练开始前写定并计算 SHA-256。之后如有任何改动，另存为 v2 并在论文中说明偏离。

## 1. 目的
检验单次划分 2×2 审计（8 个审计场景、21 个兄弟 patch）的两个结论在 9 折场景交叉验证下是否仍然成立：(a) 标签派生的 oracle 第七通道会大幅抬高 AP；(b) 同场景兄弟裁块进入训练（场景暴露）对 AP 的影响。

## 2. 设计
- 折：沿用 `scripts/mpb/cv_pipeline.py` 的 `FOLDS`（`grouped_scene_folds`，seed 20261012）。第 k 折测试，第 (k+1)%9 折验证，其余 7 折为基础训练集。
- 四格：先验通道 {NDWI, oracle} × 暴露 {clean, shared}，每格 3 个种子（0/1/2），共 9×4×3 = 108 次训练。
- 暴露剂量：测试折内 patch 数 n≥2 的场景为"可暴露场景"，其中 floor(n/2) 个 patch 作为兄弟裁块；含垃圾（MIN4）的 patch 与其他 patch 分开、各按 stem 的 SHA-256 排序后取前一半，以保证垃圾样本也被暴露。其余 patch 组成测试面板。只有 1 个 patch 的场景不参与暴露，只留在测试面板中。
- 训练规模匹配：从基础训练集随机移除与兄弟裁块数量相同的 patch（集合 R），按 `negative_category_min4` 逐类精确匹配；含垃圾部分在 2000 次带种子的抽样中选 MIN4 垃圾实例数与兄弟裁块最接近的一组（seed 20261015+k）。clean 训练 = 基础训练集；shared 训练 = 基础训练集 − R + 兄弟裁块。验证集和测试面板四格完全相同。
- 归一化：每折一个 `channel_stats_7ch.json`，只用 clean 与 shared 训练集的交集（基础训练集 − R）上的 NDWI 数组拟合，第七通道固定为 [0, 1]，四格共用（与历史单次划分审计相同的口径）。
- NDWI 通道：(1 − NDWI)/2，NDWI = (B3 − B8)/(B3 + B8)，即 `scene_7ch_ndwi_min4` 的现有数组。
- oracle 通道：对 MARIDA `*_cl.tif` 中所有已标注像元（掩膜 > 0）做 L2 距离变换，再按 patch 最大值归一化到 [0, 1]；无标注 patch 为全零。与 `scripts/preprocessing/preprocess_generate_knowledge_channel.py` 的 `mask_to_heatmap` 定义一致。
- 标签：现行三类 MIN4 标签；超参、初始化、预测收集（conf ≥ 0.001、NMS IoU 0.6、max_det 300、imgsz 512）均沿用 `cv_pipeline.py`；checkpoint 由验证集选择。

## 3. 主要终点与估计量
- 指标：垃圾类 AP50 账本（101 点插值，贪心匹配 IoU ≥ 0.5）。每格每种子把 9 折的测试面板预测合并成一个账本后计算一次 AP，再对 3 个种子取平均。
- 主分析面板：可暴露场景中留在测试面板里的 patch。
- 三个主要对比（系数与历史审计相同）：
  1. 场景暴露主效应 = ½[(shared_ndwi − clean_ndwi) + (shared_oracle − clean_oracle)]
  2. oracle 主效应 = ½[(clean_oracle − clean_ndwi) + (shared_oracle − shared_ndwi)]
  3. 交互 = (clean_ndwi − clean_oracle − shared_ndwi + shared_oracle)
- 推断：以可暴露测试场景为单位的配对场景 bootstrap，10000 次，seed 20261015，95% 百分位区间；每次重抽样四格、三个种子共用同一组场景。

## 4. 判定规则（事先写定，结果出来后不再改）
- oracle 主效应：95% 区间下限 > 0.05，判为"在场景交叉验证下复现了标签派生输入造成的大幅虚高"；区间包含 0，判为"未复现"；其余情况判为"方向一致但幅度不确定"。
- 场景暴露主效应：区间下限 > 0，判为"存在暴露虚高"，若下限还 > 0.05 则加注"且超过 0.05 AP"；区间完全落在 ±0.05 内，判为"暴露虚高小于 0.05 AP"；其余情况判为"不确定"。
- 交互：只有区间不含 0 时才写"oracle 与场景暴露存在交互"，否则写"未检测到交互"。
- ±0.05 界值沿用此前交叉验证的描述性读法，不是正式的 TOST 等效检验。
- 无论结果是否支持原结论都完整报告；与单次划分结果（暴露 +0.023、oracle +0.418、交互 −0.085）并列，并说明两者在标签体系、暴露剂量和匹配方式上的差异。

## 5. 次要分析（只作描述，不改变主结论）
- 四个简单效应：NDWI 下的暴露效应、oracle 下的暴露效应、clean 下的 oracle 效应、shared 下的 oracle 效应。
- 全面板（含单 patch 场景）重复上述分析。
- 每折平均 AP（只用可暴露场景）及其对比。
- 主要对比的逐场景 jackknife（最小值/最大值）。
- 各种子单独的 AP。

## 6. 完整性检查（任一失败即不出结果）
- 108 个 OOF 文件齐全；每个 OOF 恰好覆盖该折测试面板，场景归属正确；每个 patch 的 GT 数等于 MIN4 清单，且四格、三个种子之间 GT 完全一致。
- 每折 clean 与 shared 训练集 patch 数相等，R 与兄弟裁块逐类计数相等；clean 训练集与测试场景无交集，shared 训练集只与可暴露场景相交；验证集与训练、测试场景无交集。
- `design.json` 每次运行重新计算并与存档逐项比对一致。

## 7. 与历史单次划分审计的已知差异
- 暴露比例 50%（历史为 30%），覆盖全部 63 个场景中所有可暴露场景（历史为 8 个）。
- 训练规模按 patch 级逐类匹配（历史为按场景整体移除、beam search 匹配）。
- 标签为三类 MIN4（历史为旧七类）；NDWI 与 oracle 的定义与历史一致。
